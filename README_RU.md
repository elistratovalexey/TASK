## Форматирование текста

В **заметках задачи** и в **тексте записи базы знаний** над полем — панель: полужирный, курсив, подчёркивание, цвет текста, шрифт (без засечек, с засечками, моноширинный, рукописный), размер (мелкий, обычный, крупный, заголовок), гиперссылка, «убрать форматирование».

- Выделите фрагмент и нажмите кнопку. Без выделения кнопка задаёт стиль для следующего вводимого текста. Повторное нажатие снимает полужирный/курсив/подчёркивание.
- **Гиперссылка**: выделите текст → кнопка-цепочка → адрес (сайт, почта или путь к файлу; «weldex.ru» дополняется до https://). Когда курсор стоит в ссылке, под панелью появляется «Открыть: …»; в окне ссылки её можно изменить или убрать.
- Обычный текст хранится как раньше (поиск, Excel и синхронизация не изменились), форматирование — отдельным полем. Если текст изменить в старой версии, форматирование этой записи сбросится, сам текст сохранится.

## Кнопки «Рассчитать»

- «Начало выполнения → Рассчитать» и «Напоминание → Рассчитать»: срок минус предполагаемое время. До 8 ч — по часам (срок 10:30, оценка 30 мин → 10:00); оценка больше рабочего дня отсчитывается назад по рабочему времени из настроек. Кнопки доступны, когда задан срок.

# Мои проекты 1.0.0

## Что нового в 1.0.0

Кнопки в верхней панели (слева направо): облако, **Календарь занятости**, **Планирование**, Настройки, меню **⋮** («Задачи в Excel на почту», «Проверить обновление»).

### 1. Календарь занятости
Месяц с полосой загрузки каждого рабочего дня по плану (зелёная — свободно, оранжевая — больше 60 %, красная — день занят) и флажками сроков (красный — задача не успевается). Нажмите на день — внизу расписание: «10:15–13:00 Проверить горелку (часть 1 из 2)», сроки этого дня.

### 2. Предполагаемое время на задачу
В редакторе задачи — поля «Дней / Часов / Минут», по умолчанию 1 час. **1 день = 8 рабочих часов.** В карточке видно «Оценка: 3 ч». Старые задачи без оценки считаются по 1 часу.

### 3. Планирование и перенос сроков
Задачи выстраиваются в рабочее время начиная с текущего момента: сначала с ближайшим сроком, при равных — с высоким приоритетом; задачи без срока — в конце. Длинная задача делится на части по рабочим дням, перерыв и выходные пропускаются. Если задача не успевает к сроку, появляется предложение «Срок 22.10 12:00 → 22.10 14:15» с кнопками «Перенести» и «Перенести все». Перенос записывается в историю сроков с причиной «Планирование: не хватает рабочего времени», напоминание сдвигается на столько же. Выполненные задачи и неразобранные из почты не планируются.

### 4. Рабочее время
Настройки → «Рабочее время»: рабочие дни, начало и конец дня, перерыв. По умолчанию Пн–Пт 09:00–18:00, перерыв 13:00–14:00. Настраивается на каждом устройстве отдельно.

### 5. Задачи в Excel на почту
⋮ → «Задачи в Excel на почту»: отметьте статусы (активные, выполненные, из почты) и проекты (галочка на проекте отмечает и подпроекты), видно число задач. «Отправить» — письмо с файлом `Задачи_ГГГГ-ММ-ДД_ЧЧММ.xlsx`; «Сохранить файл» (Windows) / «Открыть файл» (Android). В файле 25 столбцов: ID, название, проект, статус, просрочена, приоритет, срок, напоминание, повторение, оценка, начало/окончание, затрачено, переносы и история сроков, чек-лист, вложения, цвет, заметки, источник письма, дата изменения. Шапка закреплена, есть автофильтр, даты — настоящие даты Excel.

Отправка идёт через SMTP. Если поля «Настройки отправки» пустые, используется ящик из «Задачи из почты» (imap.mail.ru → smtp.mail.ru, порт 465, тот же пароль приложения). Для Яндекса/Gmail — smtp.yandex.ru / smtp.gmail.com.

### 6. Обновление из облака
⋮ → «Проверить обновление» сравнивает установленную версию с опубликованной в вашем облаке (Mail или Google Диск — то, что выбрано для синхронизации).
- **Опубликовать (на ПК):** соберите MSIX и APK, в этом окне нажмите «Опубликовать версию», выберите `build\windows\x64\runner\Release\project_reminders.msix` и `build\app\outputs\flutter-apk\app-release.apk`. Версия берётся из MSIX.
- **Установить:** на другом устройстве «Проверить обновление» → «Скачать и установить». Файл проверяется по SHA-256. Windows откроет установщик MSIX, Android — установку APK (первый раз Android попросит разрешить установку из этой программы).
- Данные программы при обновлении сохраняются. Перед публикацией увеличивайте версию в `pubspec.yaml` (`version:` и `msix_version:`) и в `lib/version.dart`.

Обновите оба устройства до 1.0.0: версия 0.6 при правке задачи сотрёт оценку времени.

# Мои проекты 0.5.0

## Что нового в 0.5.0

### Задачи из почты
Перешлите письмо на отдельный ящик — программа сама создаст задачу: тема (без «Fwd:», «Пересл.:», «Re:») → название, текст письма → заметки (с отправителем и датой), вложенные файлы, картинки с именем и пересланные письма (.eml) → вложения задачи. На главном экране появится блок «Из почты: N — выберите проект и сроки» с кнопкой «Разобрать»: задачи открываются по очереди, без выбора проекта сохранить нельзя.

Настройка: Настройки → «Задачи из почты».
1. Заведите **новый** ящик, например на Mail.ru.
2. В ящике: Настройки → Безопасность → Пароли для внешних приложений → создайте пароль с доступом к почте (IMAP).
3. В программе: включите «Получать задачи из почты на этом устройстве», укажите адрес ящика, пароль и **разрешённых отправителей** — ваши адреса, с которых вы пересылаете письма.
4. «Сохранить и проверить почту».

Правила:
- Включайте приём **только на одном устройстве** (например, на ПК). Задачи придут на телефон через синхронизацию.
- Задачами становятся только письма разрешённых отправителей; обработанные письма переносятся в папку `ProjectReminders-Done`. Письма с других адресов остаются нетронутыми.
- Почта проверяется, пока программа открыта: при запуске, при каждой синхронизации и не реже раза в 15 минут.
- Письма больше 100 МБ превращаются в задачу без текста и вложений (с пометкой — открыть в почте).
- Если письмо не удалось перенести в папку, при следующей проверке дубль не создаётся.

### Чек-лист в базе знаний
В редакторе записи — блок «Чек-лист», как в задачах. В дереве у записи видно «Чек-лист: 2/5». Введённый, но не добавленный пункт добавляется при сохранении.

### Цвета строк
Палитра из 7 цветов и «без цвета»: для задач, для записей базы знаний и для каждого пункта чек-листа (кнопка с палитрой у пункта). Строка получает цветную полосу слева и лёгкий фон, текст остаётся читаемым в светлой и тёмной теме.

### Важно
Обновите **оба** устройства до 0.5.0: версия 0.4.x не примет задачи «из почты» без проекта и сотрёт цвета и чек-листы записей при их правке.

# Мои проекты 0.4.1

## Исправлено в 0.4.1: вложения не попадали в облако

- Mail: наличие файла в облаке проверяется запросом PROPFIND вместо HEAD (WebDAV Облака Mail.ru поддерживает HEAD ненадёжно, из-за этого файл не отправлялся). Папка `blobs` создаётся только если её нет.

- Настройки → «Отправить все вложения заново»: проверяет каждый файл в облаке и загружает недостающие.
- Скачивание вложений проходит по перенаправлениям сервера (пароль на чужие узлы не передаётся).

### Повторения

Повторение означает создание следующей задачи после выполнения текущей, а не бесконечный системный будильник. Укажите срок и период; у нового экземпляра сохраняется интервал между сроком и напоминанием, а пункты чек-листа становятся невыполненными.

Для ежемесячного повтора сохраняется исходный день: 31 января → 28/29 февраля → 31 марта. Если выполнить сильно просроченную задачу, следующий срок тоже может быть в прошлом; будущие даты автоматически не «перескакиваются».

Повторное открытие выполненной задачи не удаляет уже созданный следующий экземпляр. Повторное выполнение не создаёт второй экземпляр с другим ID; при независимом выполнении на двух устройствах могут появиться конфликтующие версии одного и того же ID.

Сроки и напоминания новой версии хранятся в UTC и показываются в местном времени. После переезда в другой часовой пояс проверяйте время: «9:00 в любом часовом поясе» как отдельный режим здесь не реализовано.

## Облако Mail

Mail указывает адрес `https://webdav.cloud.mail.ru` и требует пароль внешнего приложения вместо обычного пароля почты ([официальная инструкция WebDAV](https://help.mail.ru/cloud_web/app/webdav/)). Не отправляйте пароль в чат, архив исходников или резервную копию.

1. В безопасности аккаунта Mail создайте отдельный пароль внешнего приложения для этой программы.
2. В приложении выберите «Настройки → Облако → Облако Mail».
3. Укажите полный адрес почты и пароль внешнего приложения.
4. Нажмите «Сохранить настройки».
5. Вернитесь на главный экран, нажмите кнопку синхронизации и подтвердите передачу данных.
6. На втором устройстве укажите тот же аккаунт и выполните синхронизацию.

Приложение само использует HTTPS/WebDAV; подключать сетевой диск Windows или системную службу WebClient для него не нужно. Снимки записываются только в папку `ProjectReminders-v2`.

Пустое поле пароля при повторном сохранении сохраняет ранее введённый пароль. При смене почтового адреса приложение требует новый пароль, чтобы не применить пароль другого аккаунта.

Реальное подключение к вашему Mail не выполнялось. При отказе приложение покажет код HTTP; ошибки 401/403 не трактуются как пустое облако и не приводят к отправке пустой базы.

## Google Диск

Подключение Google Диска к этому чату не выдаёт вашему Flutter-приложению OAuth-клиент. Для программы необходима отдельная настройка Google Cloud; секреты вводятся локально в настройках приложения, а не в исходный код.

Обмен использует только scope `https://www.googleapis.com/auth/drive.appdata`. Google описывает `appDataFolder` как скрытое пространство данных приложения с отдельным разрешением ([официальная документация Drive](https://developers.google.com/workspace/drive/api/guides/appdata)).

### Общий проект Google Cloud

Создайте один проект, включите Google Drive API и настройте OAuth consent screen. При тестовом режиме добавьте свой аккаунт в тестовые пользователи; Windows- и Android-клиенты должны быть в этом же проекте, чтобы работать с одним пространством приложения.

### Windows

Создайте OAuth client типа **Desktop app**. Укажите выданные Client ID и Client Secret в полях Windows и сохраните настройки; для этого типа клиента секрет не считается конфиденциальным серверным секретом, но приложение всё равно хранит его отдельно в защищённом хранилище.

При первой синхронизации откроется системный браузер. Код использует PKCE, проверку `state` и временный loopback listener на `127.0.0.1`; этот вариант предусмотрен OAuth для настольных приложений ([Google OAuth for native apps](https://developers.google.com/identity/protocols/oauth2/native-app)).

Не создавайте вместо Desktop app клиента Web application с произвольным redirect URL для Windows. Введённый Desktop Client ID должен оканчиваться на `.apps.googleusercontent.com`.

### Android

Создайте OAuth client типа **Android** с package name:

```text
ru.local.projectmanager.project_reminders
```

Укажите SHA-1 сертификата, которым подписывается ваша сборка. Посмотреть signing report можно так:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
cd D:\Projects\project_reminders\android
.\gradlew.bat signingReport
cd ..
```

В том же Google Cloud проекте создайте OAuth client типа **Web application** и скопируйте его Client ID в поле «Android: Web OAuth Client ID (serverClientId)». Это параметр нативного входа Android; его Client Secret вводить в приложение не нужно.

Использование Web Client ID как `serverClientId` без `google-services.json`, а также проверка signing SHA и package name описаны в [документации Android-плагина Google Sign-In](https://pub.dev/packages/google_sign_in_android). Сверьте эти параметры до первого входа.

Код использует `google_sign_in 6.3.0` и запрашивает scope Drive при входе; приложение не читает произвольные обычные файлы вашего Диска ([описание google_sign_in](https://pub.dev/packages/google_sign_in/versions/6.3.0), [пространство данных Drive](https://developers.google.com/workspace/drive/api/guides/appdata)). Неверные package name, SHA-1 или настройки OAuth требуют исправления в Google Cloud, а не отключения проверок токена.

Первый реальный вход, обновление токена и доступ с двух устройств пока не проверены на вашем аккаунте. Для диагностики ошибки присылайте текст ошибки без токенов, паролей и OAuth Client Secret.

## Как синхронизировать без потери правок

Перед началом работы нажмите «Синхронизация», после изменений нажмите её снова. Затем выполните обмен на втором устройстве; если оба работали без сети, для полной сходимости может понадобиться ещё один обмен на первом.

Каждая передача создаёт отдельный неизменяемый снимок, а не перезаписывает общий файл. Версии записей сравниваются по счётчикам устройств, а не по часам компьютера; удаление сохраняется как специальная версия записи и не воскресает от старого снимка.

При параллельной правке одной записи откройте «Конфликты», прочитайте варианты и выберите нужный. Обычное редактирование конфликтующей записи блокируется; уведомления конфликтующей задачи приостанавливаются до выбора версии.

В 0.3.0 старые снимки, уже вошедшие в новый объединённый снимок, удаляются автоматически. Не удаляйте файлы облачной папки вручную.

Переключение Mail/Google само по себе не отправляет данные. Следующая подтверждённая синхронизация объединит текущие локальные проекты с выбранным облаком; две независимые рабочие базы для разных аккаунтов в этой версии не предусмотрены.

## Резервные копии и восстановление

В «Настройках» показаны реальные пути файла данных и папки `backups`. Перед сохранением новой базы приложение оставляет предыдущий вариант, а старые автокопии сверх 30 удаляются только из собственной папки `backups`.

Экспорт JSON включает задачи, проекты, удалённые записи и конфликтующие варианты, но не пароли и токены. Экспортируемый JSON не зашифрован; выбирайте место хранения с учётом конфиденциальности заметок.

«Восстановить из JSON» показывает число проектов и задач и требует подтверждения. Текущие данные сначала копируются; восстановление оформляется как новая правка, чтобы следующая синхронизация не вернула старое состояние автоматически.

Можно импортировать экспорт версии 2 и исходный JSON версии 1. Копия с неразрешёнными конфликтами не принимается как полная замена: сначала надо разобрать варианты; повреждённые и неизвестные форматы отклоняются.

Если основной `data_v2.json` повреждён, приложение блокирует запись вместо создания пустой базы. Закройте программу, скопируйте всю папку данных отдельно и только затем замените основной файл проверенной автокопией; файл `.previous` также сохраняет предыдущую версию. Не удаляйте повреждённый исходник до восстановления.

Автокопия рядом с базой не защищает от потери или поломки устройства. Регулярно экспортируйте JSON на другой носитель; облачные снимки тоже содержат историю, поэтому удаление задачи не равно немедленному физическому уничтожению всех её прошлых копий.

## Приёмочная проверка на ваших устройствах

- **Перенос:** старые проекты и задачи присутствуют, срок и отметка выполнения сохранены.
- **Хранение:** создать задачу, закрыть приложение, открыть и проверить; повторить без сети.
- **Чек-лист:** добавить два пункта, отметить один, перезапустить и проверить.
- **Повторение:** выполнить ежедневную задачу; проверить историю, следующий срок и сброшенный чек-лист.
- **Уведомления:** тест через 30 секунд, задача через 2–3 минуты, изменение времени, выполнение до сигнала, перезагрузка Android, закрытое окно MSIX.
- **Mail:** ПК → телефон и телефон → ПК; отдельная проверка без сети.
- **Google:** первичный вход на обеих платформах, повторный вход без нового согласия при валидном токене, обмен в обе стороны.
- **Конфликт:** на обоих устройствах изменить одну задачу без сети, затем обменять данные, выбрать версию и повторить обмен на обоих.
- **Удаление:** удалить задачу на одном устройстве, выполнить обмен на втором и убедиться, что она не воскресла.
- **Копия:** экспортировать, добавить тестовую задачу, восстановить экспорт и проверить результат.
- **Темы:** переключить светлую/тёмную, выбрать цвет и перезапустить.

Пока эти сценарии не пройдены, используйте тестовые задачи и отдельные резервные копии. Точные результаты автоматических проверок приведены в `TEST_REPORT.md`.
